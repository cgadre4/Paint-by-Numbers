## Confirmed user decisions — 2026-10-26

- **Portable CPU performance first.** Prioritize efficient algorithms, bounded memory, sensible thread/concurrency budgets and Linux/Windows CPU validation. The audited Intel machine is one measurement host, not a required hardware target. Existing optional OpenCL filtering may remain; new GPU backends are deferred and are not a gate for the first release.
- **Separate Simple and Detailed presets.** Simple should favor fewer, larger, easier-to-paint regions while retaining key facial features. Detailed should favor fidelity and disclose small/unnumbered regions. These are proposed operational definitions of the selected presets; numerical thresholds and physical print constraints still need calibration. Eye protection remains available in both.
- These choices update planning only. They do not authorize implementation or publishing before “execute.”

## Gaps to discuss before “execute”

1. **Hardware priority resolved: portable CPU performance first.** Linux/Windows CPU validation is the proposed minimum; macOS and the full supported hardware/browser matrix remain to be confirmed. New GPU backends are deferred.
2. **Preset choice resolved: separate Simple and Detailed presets.** Both should retain important facial features. Still decide how to present tiny eye regions that cannot contain numbers: color reference, separate detail sheet, leader labels, or larger physical canvas. Fully numbering every pixel-sized region at fixed print size conflicts with readable labels.
3. **Print sizes.** Suggested first contract: physical canvas sizing with A4/Letter export and optional tiling. Confirm typical canvas dimensions and minimum readable number size before changing cleanup thresholds.
4. **Execution scope.** Recommendation: approve phases 0–5 as the next release; phases 6–8 are separately reviewable milestones within the complete plan. If “execute” means all phases, include the print/edit/save and segmentation work explicitly; this is several feature iterations rather than one patch.
5. **API compatibility.** Moving decoding inside owned jobs changes when some invalid-image errors are returned. Prefer explicit versioned asynchronous errors with a transition path rather than silently breaking callers. Is the browser the only consumer?
6. **Dependencies and distribution.** A patched Pillow upgrade is required by B01. Optional GPU/segmentation libraries must earn their cost through measurements. Retain local-only behavior. Choose a public license and clarify whether macOS, Python 3.13 and non-Chromium browsers must be supported in this release.

## Approved smaller release: implementation record (2026-10-26)

The user approved the smaller browser-only release, portable CPU first, Simple and Detailed presets, and optional physical canvas size, followed by tests, benchmarks, merge to main and GitHub publication. This supersedes the planning-only paragraphs above. The original findings remain an audit snapshot, not a claim that each improvement below has shipped in full.

Completed bug fixes: B01-B12 and B14-B17, with B13's demonstrated redundant eye-filter and impossible-label distance-transform work removed. Pillow 13 and restricted decoder dispatch replace the vulnerable dependency/parser path. Normalization now belongs to a cancellable worker; uploads have admission, byte and time bounds; local Host/Origin checks run before body parsing. Request IDs cover lost responses and cancellation-before-start. Cleanup attempts every job, protects active result readers, shuts down ownership after faults, and promptly joins terminal workers to release capacity. The latter capacity race was reproduced by the two-worker load benchmark and received an additional regression.

Browser correctness now includes half-up dimensions, sRGB profile conversion, compact preview/label buffers, reset buffer release, keyboard/button panning and contrast-correct palette text. Results are read outside the registry lock; exports are cached under leases and per-job locks. Benchmark caches fingerprint producer code and publish atomically. The corrupted old local environment is left untouched; the fresh versioned environment runs the standard uv command. Dead CSS/unused imports were removed with focused lint rules; frozen benchmark references were not edited.

Improvement deliverables: shared settings/presets and versioned result/error metadata (I01); reproducible stage, sampled-RSS and job-latency diagnostics (I02); evaluated sampled clustering but retained full K-means after quality review (I03); portable CPU thread budget (I04); retained immutable color-analysis reuse (I05); compact masks and yielding highlight work (I06); presets, advanced controls, missing/eye review overlays, responsive view switching and accessible actions (I07/I12); basic physical canvas width and readability checks (part of I08); pinned CI actions, lint/advisory gates and Python 3.12/3.13 Linux/Windows checks (I13); version 1.2/runtime-only validation and documentation (part of I14); per-stage/cache/backend diagnostics and bounded owned lifetimes (part of I16).

Physical size is an export/readability option in this release. Clustering and cleanup still work in processing pixels; choosing a larger print changes millimetres per pixel, without creating detail or recalculating topology. Width is 5-200 cm, proportional height is capped at 200 cm, and a custom PDF has that exact page size. Numbers below 2 mm and custom raster density below 150 ppi produce advisory warnings. Blank width retains A4 fitting. PNG stays at processing resolution. Automatic tiling and physical-unit cleanup thresholds are not included.

Remaining improvements are explicitly deferred: a broader held-out portrait corpus and semantic quality review (I10), superpixel/graph methods and new GPU implementations (I11/I04), manual region editing and undo (I09), versioned save/reopen (I15), vector/Letter/automatic tiled exports and physical-unit merging (rest of I08), packaging/license selection and macOS/non-Chromium validation (rest of I14), crash-recovery/storage-quota controls and broader performance/p95 measurements (rest of I16/I02). Sampled clustering remains benchmark-only: favorable aggregate speed does not justify the observed eye/detail regressions. No general 25% cold-job speed guarantee or full WCAG conformance certification is claimed.

Validation and quantitative results are recorded in `benchmarks/RELEASE_1_2_RESULTS.md`. Local source and real-photo checks precede publication; exact-commit remote CI is reported only after GitHub finishes.
